## 2. Public repo, private infrastructure
19 references in the orchestration plugin to `llm.example.internal`, `atlas`, `homestack`,
LM Studio and the token path `/opt/secrets/atlas-token` (dispatch.sh, contract.md, agents, skills).
It's public: it exposes internal hostnames and makes the plugin unusable for anyone else.
**Proposal:** move endpoint, token path and model id into `.orchestra/config.json` (with neutral
defaults such as `http://localhost:1234/v1`), keep homestack-specific values in the `devcontainer`
repo (private), and phrase docs generically ("a local model server").

## 4. skill-creator and skill-reviewer
Measured today (no-skill baseline, `scripts/evals/abeval.py`): skill-creator **+0.29**,
skill-reviewer **+0.38** — both still earn their place. Proposals:
- **skill-reviewer Stage B → the script.** Today it spawns subagents in the user's session, so
  the "without skill" baseline still sees CLAUDE.md and every installed plugin (including the
  skill under test), and tokens/grades are collected by hand. Point Stage B at
  `scripts/evals/abeval.py` (isolated `claude -p --safe-mode`, evals stripped from the snapshot,
  blind judge, benchmark + report).
- **skill-reviewer rubric:** add checks for scripts + tests (Rule 9), fixture-based cases for
  "doing" skills, and the amended Rules 2/4.
- **skill-creator:** `new_skill.sh` only scaffolds `skills/<name>`; add `--plugin <dir>` for
  `plugins/*/skills/` and the opencode side. Require `assertions` at scaffold time (**done**: SKILL.md and
  `references/writing-evals.md`).
- **skill-creator evals:** cases 1 and 4 expect a finished skill in one turn, which the Stage 1
  STOP gate rightly prevents; rewrite them as two-turn cases (brief + "approved") or assert the
  gate. Its 0.6 pass rate is mostly this, not the skill.
- **Trigger overlap** with Anthropic's built-in `skill-creator`: make the description say "in
  this repo (8 authoring rules)" so the right one triggers.
